# 修复课表缩小半屏空白与缩放模糊

## Goal

让手机课表从大档位收到小档位时，预览内容始终按可用宽度铺满视口，不再出现半屏空白；同时去掉整张课表粗糙、持续的高斯模糊，保留已经验证过的跟手合成预览与松手一次落定。

## Background

- 用户截图中，2x 课表向小档位缩放时，左半屏出现大片空白，课程、表头与文字同时明显发虚。用户明确将“缩小有一半空缺”列为主要问题，模糊为次要问题。
- 当前 `app/features/schedule/hooks/useScheduleZoom.ts:192-200` 把 `scaleX` 写到 `[data-schedule-zoom-stage]`，该节点是包住滚动视口的裁剪层（`ScheduleTable.tsx:140-151`），不是完整课表内容。缩小时实际缩小的是可视窗口，因此其自身只能占据原视口的一部分。
- 当前预览平移只按窗口焦点计算（`zoomPreview.ts:91-127`），没有按完整内容的缩放边界做钳位；即使改成内容变换，也必须处理最小档位与滚动边缘，不能为了绝对固定焦点而留下空白。公式假设 `transform-origin: 0 0`，但当前网格/视口均未设置该原点，也需一并修正。
- 当前进入任意缩放相位就固定写 `blur(3px)`（`useScheduleZoom.ts:180-190`），落定后还淡出 120ms（`useScheduleZoom.ts:237-257`），所以文字和网格线在静止前的整个过程中都被模糊。
- 既有性能结论必须保留：手势期只走合成器属性，不逐帧改 `--schedule-zoom`，不跑课程格测量；三档缓存与一次性落定不是本次重做的对象。证据见 `.trellis/tasks/archive/2026-10/10-11-schedule-zoom-jank/research/README.md`。
- 外部资料对同类捏合缩放采用“固定 window + 变换 content”的两个坐标系，并在内容坐标中计算焦点与补偿平移：[Calculations for pinch to zoom](https://josiahulfers.com/calculations-for-pinch-to-zoom.html)；浏览器中的 canvas/camera 实现同样把 CSS transform 应用于内容而不是缩小视口：[Creating a Zoom UI](https://www.steveruiz.me/posts/zoom-ui)。

## Requirements

- **R1（主要：缩小无空白）**：2x→1.5x、2x→1x、1.5x→1x 的预览和落定动画中，只要缩放后的完整内容宽度不小于视口，就必须横向覆盖整个课表视口；不得出现当前这种窗口缩成半宽的大片空白。
- **R2（焦点与边界）**：有空间时仍让捏合中心下的内容点保持不动；到达左右边界或最小档位时，优先保证内容铺满，通过边界钳位放弃无法满足的焦点不变量。按钮与双击以视口中点为焦点，走同一套几何规则。
- **R3（清晰框架、局部软化文字）**：不得恢复整张课表的高斯模糊；根据用户后续明确反馈，`preview` / `settling` 期间仅对课程框内 `[data-course-content]` 的文字加 `blur(0.8px)`，掩饰横向字形变化。卡片底色、描边、网格线、表头、出勤角标与控件保持清晰；落定后文字立即恢复，不做滤镜淡出。
- **R4（性能不退化）**：手势期不提交 React 状态、不改变真实网格宽度、不执行课程格适配；仍只在进入手势时读取一次几何，逐帧只写合成器 `transform`。
- **R5（既有行为保持）**：双指、−/+、双击仍吸附 1 / 1.5 / 2；落定后 `scrollLeft` 与真实内容位置一致，课程格字号/换行/信息显隐、单指滚动、边缘切周、双击去抖及减少动效语义不变。
- **R6（契约同步）**：若预览宿主或滚动溢出约束需要调整，必须同步更新源码守卫、观测锚点说明和 `mobile-schedule-layout.md`，不能让规范继续声称变换挂在旧视口层。

## Acceptance Criteria

- [x] **AC1（缩小覆盖）**：浏览器中以 2x 为起点，在 `scrollLeft = 0 / 中间 / 最大` 与焦点偏左 / 居中 / 偏右的代表组合下执行缩小；预览至 1.5x 与 1x 时，完整内容相对滚动容器**内容盒**的 `left ≤ 0.5px` 且 `right ≥ viewportWidth − 0.5px`，无半屏空白。− 按钮和双击的 2x→1x 路径也覆盖同一判据。
- [x] **AC2（焦点与边界数学）**：纯函数单测钉住内容坐标焦点公式；未触边时焦点不动，触边时平移被夹到可覆盖视口的区间，最小档位下内容恰好铺满。
- [x] **AC3（终态）**：三条入口落定后网格宽度、`scrollLeft` 和档位正确；所有预览内联样式与相位锚点清空；课程格逐格回归无新增违规。
- [x] **AC4（仅文字局部模糊）**：`preview` / `settling` 的 stage 与 grid 均无 filter，所有 `[data-course-content]` 为 `blur(0.8px)`；`idle` 的课程文字恢复 `none`，其他内联预览样式与相位清空。减少动效偏好仍直接落定。
- [x] **AC5（性能与手势）**：复用生产构建 + CDP 双指探针，手势期最大帧间隔 ≤50ms、无 ≥50ms 长任务，真实网格布局宽度与 React 档位不变；单指滚动、课程点按和边缘切周不回归。
- [x] **AC6（规范与门禁）**：相关单测、源码守卫与规范更新；`pnpm test`、`pnpm typecheck`、`pnpm lint`、`pnpm format:check`、`pnpm build`、`pnpm webview:check-css`、`pnpm test:android-assets` 全绿。

## Out of Scope

- 不新增缩放档位，不改成整页浏览器缩放，不引入 html2canvas/截图缩放或新的动画库。
- 不重做课程格排布缓存、预热机制、配色、行高、字号公式或课程数据。
- 不通过简单跳过缩小预览来规避空白；除非实验证明内容变换在当前 WebView 目标基线上不可行，再另行提交降级方案复核。
- 不自动提交、不发布版本；真机观感需用户在设备上复核。

## Deferred / Risk

- 规划期动态探针已完成 18 组缩小组合：内容均覆盖视口，`scrollLeft` 未被自动钳走；放大时的临时视觉溢出及其与紧接横滑的交叉仍需在实施后用产品状态机复验。若出现实际手势干扰，再采用保持原滚动盒几何的裁剪/占位结构，不逐帧读布局或回退到实时重排。
- 用户复核后明确选择“缩放过程中保留课程框内文字模糊”，以掩饰纯 `scaleX` 造成的字形拉伸；最终取舍是局部 `0.8px`，不恢复整表模糊。局部滤镜仍需复测手势帧率和长任务。
